# 町工場の見積アシスタント（デモ）

デモ: https://mfg-quote-assistant.vercel.app （架空の会社・書類です）

製造業の社内文書（PDF 13 本）に質問すると、回答と**根拠**（書類名・ページ・該当箇所）を返します。
問い合わせメールを貼れば、図番・数量・納期を読み取り、過去見積と社内規程から見積の下書きを作り、
そのあとに出す社内確認とお客さんへの一次回答の文面まで組み立てます。
金額の計算はコード側に閉じ、**LLM には文面の整形だけ**をさせています。単価・値引・短納期割増は
テストで固定してあるため、モデルを替えても金額は変わりません。過去実績の無い部品は単価を作らず
**「未見積」**とし、合計金額も**「未確定」**と明示したうえで、仕様の近い過去部品を根拠つきで示します。
書類・会社名・図番はすべて架空です。

構成は Next.js（TypeScript）＋ Python。既定では外部 API を一切呼ばない `mock` で動作し、
環境変数ひとつで Claude に切り替わります。

## 何ができるか

### 1. 書類に質問する（`/ask`）

![書類に質問する画面](docs/screenshots/ask.png)

質問を投げると、回答と**根拠カード**（書類名・ページ・該当箇所の抜粋）が出ます。
カードを押すと書類ビューアの該当ページへ飛び、引用元がハイライトされます。

| 質問 | 返るもの |
| --- | --- |
| SS-1023 を前回いくらで出した？ | 直近の見積番号・発行日・数量・単価・金額・納期と、過去 2 件の実績 |
| 短納期の割増は何％？ | 10/7/5 営業日の 3 区分と、値引のあとに掛ける旨 |
| SF-2040 の材質と表面処理は？ | 材質・表面処理・寸法・公差・最小ロット・標準納期 |
| CV-3015 を前回いくらで出した？ | **「書類からは見つかりませんでした」**（仕様書はあるが、過去見積が無い図番） |

4 つめが重要です。該当が無いときに単価をでっち上げないことを、動く形で示しています。

`/ask?q=<質問>` で、特定の質問を開いた状態のリンクを共有できます。

### 2. 問い合わせ文から見積の下書き（`/quote`）

![見積の下書き画面](docs/screenshots/quote.png)

問い合わせメールを貼ると、図番・数量・希望納期を読み取り、過去見積と社内ルールから
単価を組み立てます。出るのは金額だけではありません。

- **単価の根拠**：「過去見積から基準単価 → 数量値引 → 短納期割増」を 1 段ずつ、
  いくらからいくらになったか・どの書類の何ページを使ったかつきで表示します。
- **人が確認すべき点**：そのまま出してはいけない理由を列挙します。
- **確定していない金額を確定値として出さない**：単価を出せない明細が 1 つでもあると、
  金額欄は「小計（単価確定分のみ）」になり、合計欄には「未確定」と出ます。

サンプル①（SS-1023 を 150 個・10 営業日）の実際の出力：

```
数量 100 個 2,310 円 と 数量 200 個 1,980 円 の間を内挿   → 2,145 円
100 個以上のため 3% 引き（社内見積基準 4. 数量値引基準 p1） → 2,081 円
10 営業日以内のため 20% 増し（同 5. 短納期割増率 p1）      → 2,497 円
合計 374,550 円（消費税別）

人が確認すべき点（1 件）
・参照した見積 Q-2026-0325（2026-03-25）は材料費改定日 2026-07-01 より前のものです。
  鋼材は 8% 引き上げられているため、反映の要否を確認してください。
```

サンプル②では、過去見積が 1 件しか無い図番（内挿できない）と、
過去見積がまったく無い図番（下書きを作らない）が同時に出ます。後者があるため、

```
SF-2040  数量 60   5,600 円   336,000 円   18 営業日
CV-3015  数量 30   未見積（過去見積なし）     14 営業日

                 小計（単価確定分のみ・消費税別）   336,000 円
                 合計（消費税別）                   未確定

人が確認すべき点（4 件）
・CV-3015 の単価が確定していません。小計 336,000 円は単価が確定した明細だけの金額で、
  見積の合計額ではありません。
・SF-2040: 参照できる過去見積が Q-2026-0521 の 1 件のみです。…
・SF-2040: 参照した見積 Q-2026-0521（2026-05-21）は材料費改定日より前のものです。…
・CV-3015: 図番 CV-3015 の過去見積が書類の中に 1 件もありません。…
```

というように、**小計を合計額として出しません**。これは `quote.ts` が
`hasUnquotedItems` として返す値で決まり、vitest で固定しています。

![単価を出せない明細がある場合の見積下書き](docs/screenshots/quote-unquoted.png)

*過去見積が無い部品は単価を作らず「未見積」と表示し、小計が合計ではないことを明示する*

`/quote?sample=inquiry-01`（または `inquiry-02`）で、サンプルを流し込んだ状態のリンクを共有できます。

#### 次の一手

下書きの下に、**次にやる仕事の文面**を 2 つ畳んで置いています。下書きを出して終わりにすると、
そのあとの往復が結局は人の頭の中に残るためです。

- **社内の確認依頼（ベテラン宛て）**：「人が確認すべき点」をそのまま質問の形にしたもの。
  未見積の図番があれば `/similar?part=…` へのリンクを添えます。
- **お客さんへの回答メール下書き**：単価確定分は金額を書き、未見積の明細は
  「単価は確認のうえ、3 営業日以内にご回答します」とします。

サンプル②の回答メール下書き（実際の出力）：

```
・SF-2040  数量 60  単価 5,600 円  金額 336,000 円  納期 18 営業日
・CV-3015  数量 30  単価は確認のうえ、3 営業日以内にご回答します  納期 14 営業日

単価をお示しした分の小計は 336,000 円（消費税別）です。
CV-3015 の単価が未確定のため、全体の合計金額は現時点では確定していません。
```

未確定の合計を確定値として書かないことを、vitest で固定しています
（文面に `合計 ◯◯ 円` が現れないこと）。文面は `lib/followup.ts` の
決定的なテンプレートで、LLM を通していません。

### 3. 類似品から相談する（`/similar`）

![類似品から相談する画面](docs/screenshots/similar.png)

過去見積が無い図番でも、**仕様の近い部品の実績**なら示せます。ただし
**この画面は単価を作りません**。単価欄・合計欄は「未確定」のままです。

出すのは次の 4 つです。

- **対象図番の仕様**（仕様書の該当ページへの根拠リンクつき）
- **類似候補**（上位 3 件まで）。工法・材質・板厚・外形寸法・表面処理・公差・最小ロットを
  1 項目ずつ並べ、一致／近い／相違を判定します。候補の過去見積は見積番号・日付・数量・単価を
  根拠リンクつきで出し、単価の横には必ず**「参考値。この図番の単価ではありません」**を添えます。
- **振れる方向**：「材質 SPCC t1.6 → SUS304 t1.5 ↑ 上がる方向」のように、
  矢印と言葉だけで示します。**率も金額も出しません**（根拠のある係数を持っていないため）。
- **人が確認すべき点**：`/quote` と同じ書き方で並べます。

CV-3015（過去見積の無い図番）の実際の出力：

```
候補 1  CV-2980  カバー                              類似度 0.927
  工法 板金 / 板金  材質 SUS304 t1.2 / SUS304 t1.5  表面処理 一致  公差 一致
  Q-2026-0612（2026-06-12）数量 50  2,740 円  参考値。この図番の単価ではありません
  板厚   1.2 → 1.5   ↑ 上がる方向
  外形寸法 280x140 → 300x150  ↑ 上がる方向

候補 2  PL-1150  取付プレート                        類似度 0.654
  材質 SPCC t1.6 → SUS304 t1.5  ↑ 上がる方向（鋼材からステンレス）
  表面処理 ユニクロメッキ → バフ研磨 #400  ? 判断できない

単価 未確定 / 合計 未確定
```

類似度が下限（0.45）に届く候補が無ければ、**候補を並べずに「近い部品が書類の中にありません」**
と返します。実際、SF-2040（切削）に対する候補は下限未満しか無く、そう返ります。
かすっただけの候補を並べると「近い部品がある」と誤読されるため、
`answer.ts` の下限スコアと同じ考え方で切っています。

`/similar?part=CV-3015` で、特定の図番を開いた状態のリンクを共有できます。

## 設計の要点

### 計算は決定的、LLM は整形だけ

見積の金額を LLM に出させると、桁や適用区分を静かに間違えたときに誰も気づけません。
そこで責務を切ってあります。

```
単価・値引・割増・納期   → web/lib/quote.ts   TypeScript の純粋関数（LLM を通さない）
回答に使ってよい事実     → web/lib/answer.ts  検索結果と構造化データから決定的に生成
日本語の文面            → web/lib/llm/*      LLM はここだけ
```

LLM に渡すのは**計算済みの数字だけ**で、プロンプトでも「与えられた事実の外に出るな」
「足りなければ無いと言え」を明示しています。だからモデルを替えても金額は動きません。
`/ask` の「この回答の組み立て方」を開くと、LLM に渡した事実そのものが見られます。

副作用として、金額まわりはすべてテストで固定できます（`web/tests/quote.test.ts`）。

### なぜ埋め込みでなく BM25 か

図番（`SS-1023`）や率（`3%`）のような、短くて正確さが要る語を取りこぼさないためです。
ベクトル検索はこの手の語に弱く、しかも埋め込みの生成に外部 API が要ります。

日本語は形態素解析器を使わず**文字 bi-gram**にしています。辞書に載っていない図番や
材質記号をかえって誤分割するためです。英数字は区切りを含む丸ごと（`ss-1023`）と
分解した形（`ss` / `1023`）の両方を索引します。

bi-gram は「ブラケット」と「ロボット」が `ット` を共有するような誤ヒットを生みます。
そこで `answer.ts` に下限スコアを置き、かすっただけの結果は
「見つかりませんでした」に倒しています。

### なぜ pdfplumber の表抽出か

見積書の金額は罫線つきの表に入っています。テキストを空白で分割する方式だと、
`SPCC t3.2` のように**値の中に空白を含むセル**で列が 1 つずれ、単価と金額が入れ替わります。
pdfplumber の `extract_tables()` は罫線からセル境界を復元するので、これが起きません。

表に入っていない値（合計金額）だけ、ページテキストに正規表現を当てています。

### 根拠のページがずれない作り

チャンクは**ページをまたぎません**。またぐと「何ページ目か」が一意に決まらず、
根拠として示せなくなるためです。章見出しで切り、見出し行はチャンク本文の 1 行目として
残します（抜粋だけ見て何の話か分かるように）。

## 構成

```
┌─ data/source/*.yaml ──┐   架空書類の元データ（人が読み書きする唯一の場所）
│                       │
│   make_pdfs.py        │   IPAexゴシックを埋め込んで A4 PDF を生成
├─ data/pdf/*.pdf ──────┤
│                       │
│   extract.py          │   pdfplumber：ページ単位のテキスト＋罫線表
│   chunk.py            │   見出し単位・ページをまたがないチャンク
│   fields.py           │   表のセルから金額・材質・納期を構造化
│   build_index.py      │
├─ web/public/*.json ───┤   index.json（検索用）/ quotes.json（構造化データ）
│                       │
│   lib/bm25.ts         │   検索
│   lib/answer.ts       │   事実の組み立て（決定的）
│   lib/quote.ts        │   見積計算（決定的）
│   lib/similar.ts      │   類似度と「振れる方向」（決定的・単価は作らない）
│   lib/followup.ts     │   次の一手の文面（決定的・LLM を通さない）
│   lib/llm/*           │   文面の整形だけ（mock / claude）
└─ app/ ────────────────┘   /ask /quote /similar /docs/[id]
```

```
mfg-quote-assistant/
  data/
    source/      架空書類の元データ（YAML / Markdown）
    pdf/         生成した PDF（コミット済み）
    fonts/       IPAexゴシック（IPAフォントライセンス v1.0 同梱）
  ingest/        Python：PDF 生成・抽出・チャンク化・項目抽出（pytest 48 件）
  web/           Next.js App Router + TypeScript（vitest 149 件）
```

## ローカルで動かす

### 1. 書類と検索インデックスを作る（任意）

生成物はコミット済みなので、元データを書き換えないかぎり不要です。

```powershell
cd ingest
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"

python -m ingest.make_pdfs     # data/source/*.yaml -> data/pdf/*.pdf
python -m ingest.build_index   # data/pdf/*.pdf -> web/public/*.json
python -m pytest
```

macOS / Linux では `source .venv/bin/activate` を使ってください。

### 2. 画面を起動する

```powershell
cd web
npm install
npm run dev
```

http://localhost:3000 を開きます。`/ask` と `/quote` はサンプル入力のボタンから試せます。

### 3. 検査を通す

```powershell
cd web
npm run lint
npm run typecheck
npm test
npm run build
```

## Claude に切り替える

既定は `mock` です。`LLM_PROVIDER` が未設定・空・未知の値のいずれでも `mock` になり、
`claude` と明示したときだけ Anthropic API を呼びます。
`lib/llm/claude.ts` は動的 import なので、`mock` のあいだは Anthropic SDK 自体が読み込まれません。

```powershell
# web/.env.local（git 管理外）
LLM_PROVIDER=claude
ANTHROPIC_API_KEY=sk-ant-...
ANTHROPIC_MODEL=claude-opus-5-5   # 省略可
```

切り替えても変わるのは文面だけです。金額・根拠・「人が確認すべき点」は同じものが出ます。
現在どちらで動いているかは画面フッターに出ます。

> 従量課金が発生します。テスト・ビルド・CI はすべて `mock` のまま通ります。

## 収録している架空書類

| 書類 | 内容 |
| --- | --- |
| 部品仕様書 ×6 | SS-1023 ブラケット（板金）/ CV-3015 カバー（板金）/ CV-2980 カバー（板金）/ PL-1150 取付プレート（板金）/ SF-2040 シャフト（切削）/ BS-4070 ブッシュ（切削） |
| 過去見積 ×6 | SS-1023 が 3 件（50 / 200 / 100 個、材料費改定をまたぐ）、SF-2040・CV-2980・PL-1150・BS-4070 が各 1 件。**CV-3015 は 0 件** |
| 社内見積基準 ×1 | 数量値引・短納期割増・最小ロット・最低受注金額・材料費改定日・標準納期 |
| 問い合わせメール ×2 | `/quote` のサンプル入力（PDF にはしていません） |

部品は、CV-3015 から見て「近いもの」（CV-2980：同じ板金・同じ SUS304・同じバフ研磨）と
「遠いもの」（BS-4070：切削・黄銅）が両方できるように選んであります。
`/similar` の下限が効いていることを、動く形で見せるためです。

デモが成立する前提（CV-3015 に見積履歴が無いこと、SF-2040 が 1 件だけであること、
SS-1023 が 3 件であること）は pytest で固定しています。
書類を差し替えると、この前提が崩れた時点でテストが落ちます。

## 制約・未対応

- 認証・DB は入れていません。データは静的 JSON です。
- 数量の内挿は実績の範囲内だけで、範囲外では外挿せず最近傍の単価を使い、確認事項に出します。
- 社内ルールの数値は YAML を正としています（散文からの正規表現抽出は壊れやすいため）。
  ただし根拠として示すページ番号は PDF の抽出結果から引くので、PDF とずれるとテストが落ちます。
- 最低受注金額（30,000 円）を下回る分岐は、現在の架空データでは到達しません。
- `/similar` の類似度の重み（工法 0.35／材質 0.20／板厚 0.15／外形 0.10／表面処理 0.10／
  公差 0.05／最小ロット 0.05）と下限 0.45 は、実データで調整したものではありません。
  「工法が違えば使えない」という優先順位を形にしただけで、現場で使うなら実績に当てる必要があります。
- `/similar` の「振れる方向」は上がる／下がる／判断できないの 3 値だけです。
  率や金額を出さないのは、根拠のある係数を持っていないためで、意図した割り切りです。

## ライセンス・素材

`data/fonts/ipaexg.ttf` は IPAexゴシック（IPAフォントライセンス v1.0）です。
ライセンス全文を同ディレクトリに同梱しています。
